# API Reference

Interactive, always-current docs are auto-generated by FastAPI at `GET /docs` (Swagger UI) and `GET /redoc` whenever the server is running — this file is a narrative companion, not a replacement.

**Base URL:** `http://localhost:8000` (local/Docker Compose default) · **Auth:** `Authorization: Bearer <token>` header, obtained from `POST /auth/login`.

Every error response uses the same envelope:

```json
{"error": "not_found", "message": "Conversation not found.", "request_id": "..."}
```

## Auth

| Method | Path | Auth | Notes |
|---|---|---|---|
| `POST` | `/auth/login` | — | Rate-limited (5/60s per IP). Returns `{access_token, token_type}`. Wrong password and unknown email return **identical** 401s — anti-enumeration. |

## Users

| Method | Path | Auth | Notes |
|---|---|---|---|
| `POST` | `/users` | — | Signup. Rate-limited (10/60s per IP). Password: 8–128 chars. No `role` field accepted — self-service privilege escalation is structurally impossible. Duplicate email → `409`. |
| `GET` | `/users` | Admin | List every user. |
| `GET` | `/users/me` | Any authenticated user | The calling user's own profile. |

## Documents

| Method | Path | Auth | Notes |
|---|---|---|---|
| `POST` | `/documents` | Required | Multipart upload. `202 Accepted` — ingestion (extract → chunk → embed → index) runs as a background task. Rejects unsupported content-type (`415`) or oversized files (`413`) synchronously, before storing anything. Supported: `text/plain`, `text/markdown`, `application/pdf`. |
| `GET` | `/documents` | Required | List the caller's own documents only. |
| `GET` | `/documents/{id}` | Required | `404` for a nonexistent ID **or** another user's document — identical response either way. |
| `GET` | `/documents/{id}/status` | Required | Lightweight polling endpoint — `uploaded → processing → embedding → ready`/`failed`, plus `error_message` when failed. |
| `DELETE` | `/documents/{id}` | Required | Removes the file, its vector chunks, and the DB row, in that order (see [`backend-architecture.md`](backend-architecture.md) for why that order matters). |

## Chat

| Method | Path | Auth | Notes |
|---|---|---|---|
| `POST` | `/chat` | Required | `{question, conversation_id?}` → `{answer, tool_used, citations[], conversation_id}`. Omit `conversation_id` to start a new conversation. Empty question → `400`. |
| `POST` | `/chat/stream` | Required | Same request shape; response is `text/event-stream` (Server-Sent Events) — incremental `{"delta": "..."}` frames, then a final `{"done": true, "tool_used", "citations"}` frame. |

## Conversations

| Method | Path | Auth | Notes |
|---|---|---|---|
| `POST` | `/conversations` | Required | Create an empty conversation (e.g. to show in a sidebar before a first question exists). |
| `GET` | `/conversations` | Required | List the caller's own conversations, most-recently-active first. |
| `GET` | `/conversations/{id}` | Required | Full detail including every message, chronological. |
| `DELETE` | `/conversations/{id}` | Required | Cascades to delete every message in it. |

## Health, Status, Metrics

| Method | Path | Auth | Notes |
|---|---|---|---|
| `GET` | `/` | — | Basic service info. |
| `GET` | `/health` | — | Liveness only — no dependency checks, always fast. |
| `GET` | `/health/ready` | — | Readiness — checks database, ChromaDB, storage (hard dependencies, `503` if any fail); LLM reported informationally (`not_loaded_yet` is healthy). |
| `GET` | `/status` | — | Descriptive dependency status, no pass/fail verdict. |
| `GET` | `/metrics` | — | Prometheus exposition format — HTTP and AI-specific series (request counts/latency, token usage, estimated cost, retrieval quality). |
| `GET` | `/internal/ai-metrics` | Admin | Human-readable JSON summary of the same AI metrics — for local debugging/demos, not scraping. |

## Example: full RAG round-trip

```bash
# 1. Sign up and log in
curl -X POST localhost:8000/users -H 'Content-Type: application/json' \
  -d '{"email":"demo@example.com","name":"Demo","password":"secret123"}'
TOKEN=$(curl -X POST localhost:8000/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"demo@example.com","password":"secret123"}' | jq -r .access_token)

# 2. Upload a document
curl -X POST localhost:8000/documents -H "Authorization: Bearer $TOKEN" \
  -F "file=@postmortem.txt;type=text/plain"

# 3. Poll status until "ready", then ask a grounded question
curl -X POST localhost:8000/chat -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"question":"What caused the outage described in the postmortem?"}'
```
